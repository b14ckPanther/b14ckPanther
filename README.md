  <img src="assets/sections/darb-built-dark.svg?v=4b5d8da" width="100%" alt="How it's built. Our own backend: No backend-as-a-service. We wrote the NestJS API for search, places, media, admin, helpers and pricing on our own PostgreSQL schema (PostGIS and pgvector), with Redis for caching and rate limits. The API and the web app share the same zod contracts, so a field that doesn't match breaks the build instead of production. Clerk handles sign-in, and that's the only outside service in the core. Search in two steps: Results appear instantly from an index in the browser while you type. Then a language model works out what you meant, with a strict schema and 1.5 seconds to answer, and matches it against what each business offers, down to single menu items. If the model is slow, you still have the instant results. One map for everything: Country, town, category and business are the same MapLibre map at different zoom levels. We host the vector tiles ourselves on Cloudflare R2, so there's no bill per map view and nobody tracking our users. Data you can trace: Listings come from government registers and OpenStreetMap, deduplicated and geocoded. Where the open maps miss a town, Darb Helpers and our own street capture fill the gap, and every addition gets reviewed before it goes live. A red build doesn't ship: Every pull request runs type checks, about 1,500 unit and integration tests against a real database, Playwright on desktop and phone, WCAG AA checks on every page, performance budgets per route, and 103 real search queries that catch drops in result quality. Stack: Next.js 16, NestJS, Prisma, PostgreSQL, PostGIS, pgvector, Redis, MapLibre GL, Cloudflare R2, Railway, Vercel, Turborepo."/>
</picture>
